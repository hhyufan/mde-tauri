# 本地脚本运行

打开 `.cs`、`.js`、`.mjs`、`.cjs`、`.py`、`.java`、`.kt`、`.kts` 或 `.rs` 文件，编辑器右上角自动显示悬浮运行按钮。按 **F5** 或点击该按钮，程序使用按下运行时的最新编辑内容，结果实时显示在编辑器下方的输出控制台。运行时按钮切换为停止。

| 操作 | 使用方式 |
| --- | --- |
| 运行当前文件 | F5 或运行按钮 |
| 停止运行 | Shift+F5 或停止按钮 |
| 调整控制台高度 | 拖动控制台顶部边缘 |
| 输入内容 | 在底部输入框输入，Enter 或“发送”提交一行 |
| 隐藏、重新打开 | 关闭按钮隐藏，标题栏控制台按钮重新打开；切换到其他文件时控制台自动隐藏；隐藏时运行继续、输出保留 |
| 复制、清空 | 控制台右上方按钮 |

控制台显示标准输出、标准错误、退出码和运行时间。输入框支持 Python 的 `input()`、C# 的 `Console.ReadLine()`、Node.js 的标准输入，以及 Java 的 `Scanner`/`System.in` 和 Kotlin 的 `readln()`。输入法组词阶段的回车不会提交输入。运行中再次按 F5 会显示当前控制台，不会重复启动进程。

## 运行环境

- **JavaScript**：本地 Node.js，支持 CommonJS 和 ES modules。
- **Python**：本地 Python 3，使用无缓冲输出模式。
- **C#**：本地 .NET 6 或更高版本 **SDK**，支持顶层语句和 `Program.Main`。以单文件控制台应用编译；不自动下载 NuGet 包或加载已有工程的项目引用。
- **Java**：本地 **JDK**（需要 `javac`）。源码快照按 `public` 类名命名（无 `public` 类时用第一个类，再退回文件名或 `Main`），由 `javac` 编译到缓存目录后交给 `java` 启动；支持 `package` 声明。
- **Kotlin**：本地 Kotlin 编译器 `kotlinc`，另需 `java` 运行编译产物。`.kt` 编译成自包含 jar 后运行；`.kts` 脚本直接用 `kotlinc -script` 执行，不做编译缓存。
- **Rust**：本地 `rustc`，按 Rust 2021 编译后运行，支持未保存的源码、相对模块、交互输入、停止和编译错误输出。Windows 需要 MSVC C++ 工具链及 Windows SDK，自动寻找完整的 Visual Studio/Build Tools 安装。单文件没有外部依赖且源码未变时复用编译缓存，包含模块或 include 等依赖时重新编译。

检测顺序为：手动配置 → 专用环境变量（Java 的 `JAVA_HOME` / `JDK_HOME`、Kotlin 的 `KOTLIN_HOME`、.NET 的 `DOTNET_ROOT`）→ `PATH` → 系统安装目录。环境变量无效时继续查找。Windows 系统搜索包括常见发行商安装目录、用户的 `.jdks` / SDKMAN / Scoop 目录、开发工具目录旁的安装，以及系统盘的 `Env` / `Tools` / `Dev` 等目录；同一目录下的 JDK 优先选择较新版本，Java 的编译器和运行器使用同一套 JDK。

Kotlin 的编译和 `.kts` 解释阶段都会收到检测到的 `JAVA_HOME` 与 Java 所在的 `PATH`，因此搜索到的 JDK 即使原本没有加入系统 `PATH` 也能使用。未找到环境时，控制台显示原因；展开“运行环境”，填写或浏览选择 `node.exe`、`python.exe`、`dotnet.exe`、`java.exe`、`kotlinc.bat` 等可执行文件，或直接填它们的安装目录（JDK 主目录、JDK 的 `bin`、Kotlin 的 `bin` 都可以）。Java 填 `javac.exe` 也能跑：编译用它，运行会自动改用同目录的 `java`。配置只保存到本机。展开面板时输出区暂时让位给设置，收起后恢复；控制台高度不足时面板自身滚动，不会把底部输入栏挤出控制台。

已有文件以所在目录为工作目录，JavaScript/Python 的相对导入可以找到旁边的文件。运行使用内容快照；JavaScript/Python 的临时快照在完成后清理，C#、Java、Kotlin 在应用缓存目录中保留最近一次源码与编译产物。F5 本身不会覆盖原文件。Windows 使用进程组管理运行，停止或关闭应用时会一起终止脚本的子进程。

C# 首次运行需要编译，因此会比 JavaScript/Python 启动慢。后续修改复用项目还原和增量编译缓存；代码未修改且上次成功时直接启动已编译程序，跳过编译。修改源码或编译失败会使这项缓存失效，避免运行旧代码。

Java 与 Kotlin 同样是“先编译再运行”：编译阶段的标准输出与错误直接显示在控制台，编译失败就不会启动程序，退出码取自编译器。源码未变且上次编译成功时跳过编译，直接启动缓存产物；Kotlin 首次运行需要启动编译器、编译源码并打包标准库，缓存命中后只做一次 `java -jar`。JVM 的 `file.encoding`、`stdout.encoding` 等属性被固定为 UTF-8，中文输出不会乱码。

## Markdown 代码块运行

Markdown 分栏预览和所见即所得模式会在支持的代码块右上角显示“运行”。语言标记支持 `cs` / `csharp` / `c#`、`js` / `javascript`、`py` / `python`、`java`、`kt` / `kts` / `kotlin`、`rs` / `rust`，其他语言和行内代码不显示运行入口。

点击后仅执行该代码块，标准输出、错误、退出码、耗时显示在代码块底部。每个代码块分别保留结果，运行时可单独停止；同时最多运行 8 个脚本。需要交互输入时，结果区域提供输入框，输入法选词的回车不会提交。

代码块以 Markdown 文件所在目录为工作目录，使用当前代码正文；不会把 Markdown 围栏或其他代码块传给解释器。运行结果只保存在本次应用的内存中，不写入 Markdown 或参与云同步。修改已经运行过的代码会提示重新运行。

运行环境与文件运行共用控制台中的本地配置，各语言的编译缓存按代码块隔离。

## 示例

JavaScript：

```javascript
console.log('JavaScript 运行成功');
console.log(6 * 7);
```

Python：

```python
name = input('你的名字：')
print(f'你好，{name}')
```

C#：

```csharp
Console.Write("你的名字：");
var name = Console.ReadLine();
Console.WriteLine($"你好，{name}");
```

## 开发验证

`npm run test` 验证快捷键、最新缓冲区、输出事件顺序、输出长度限制和输入法提交。执行全部原生运行测试需要本机安装 Node.js、Python、.NET SDK、JDK 和 Kotlin 编译器：

```text
cargo test --manifest-path src-tauri/Cargo.toml script_runner::tests -- --include-ignored --test-threads=1
```

测试包含环境变量优先级、系统目录搜索、Java/Kotlin 中文输出、Kotlin 脚本交互输入、相对导入、无限循环停止和子进程清理。默认 Rust 测试将需要本地运行环境的测试标为 ignored，使没有安装解释器的环境仍可检查其他功能。
