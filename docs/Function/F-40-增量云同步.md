# 增量云同步

## 功能边界

这里的“增量”指按文档变化同步：本地只处理 durable outbox 中的脏文档，远端只拉取 checkpoint 之后的变更事件。单次 upsert 仍是带 SHA-256 校验的完整正文快照，并不是文本 diff、分块上传或 CRDT。

同步遵守 local-first：磁盘保存不等待网络；关闭同步或离线时，已纳入同步的编辑仍先进入持久 outbox，恢复网络或重新启用后继续发送。

## 架构

- [syncEngine.js](../../src/services/syncEngine.js)：协调配置、对账、拉取、outbox 消费、冲突与重试。
- [syncTransport.js](../../src/services/sync/syncTransport.js)：唯一了解 `/sync/*` HTTP 形状的传输层；不暴露 reset 操作。
- [useSyncStore.js](../../src/store/useSyncStore.js)：按账号保存 catalog、outbox、checkpoint、conflict 和运行结果。
- [contentCodec.js](../../src/services/sync/contentCodec.js)：UTF-8/gzip 编解码、请求体限制、size 与 SHA-256 完整性校验。
- [changeProtocol.js](../../src/services/sync/changeProtocol.js)：兼容 v2 时间戳 cursor 与 v3 opaque seek cursor。
- [retryPolicy.js](../../src/services/sync/retryPolicy.js)：区分暂时错误与永久错误，并处理 `Retry-After`。
- 后端入口：[sync.controller.ts](https://github.com/hhyufan/mde-server/blob/main/src/sync/sync.controller.ts) 与 [sync.service.ts](https://github.com/hhyufan/mde-server/blob/main/src/sync/sync.service.ts)。前后端拆仓后，协议改动必须同时跑契约测试。

## 一轮同步

1. 等待本地同步状态 hydration，并把崩溃遗留的 `processing` lease 恢复为 `pending`。
2. 同步可跨设备共享的设置；设备本地的 `workspacePath`、`serverUrl`、`syncEnabled` 不上传。
3. 扫描已纳入同步的本地文件和 external 缓存，修复暂停、崩溃窗口造成的漏入队。
4. 先拉远端变更，让并发编辑在推送前形成显式冲突。
5. 逐条 claim outbox；请求发出前必须完成持久化。每条 operation 固定使用入队时的 `baseRev` 和 `mutationId`。
6. 再拉一次远端，接收本轮服务端确认和并发变化。

同一文件严格保持操作顺序，不同文件可以独立前进。一个文件的 conflict/terminal error 会阻塞该文件的后继操作，但不会卡住其他文件。

## 数据安全不变量

- 协议或本地 schema 升级不得由客户端删除远端数据，也不得清空本地 outbox。
- `localChecksum` 表示当前本地快照；`serverChecksum` 只表示最后一次已确认的服务端基线，二者不能复用。
- conflict、被阻塞的 operation 与文档 revision 必须在一次 store commit 中写入；用户裁决前，自动保存不能移除 conflict barrier。
- “保留本地”会基于冲突中的远端 revision 创建一个新 operation；发送时禁止把旧 operation 偷偷 rebase 到新 revision。
- 正文解压、size/hash 校验或本地落盘失败时，不得把该事件当作普通成功越过 checkpoint。
- checkpoint 只在整页事件都达到 durable terminal state 后推进；cursor 声称 `hasMore` 却不前进属于协议错误。
- 账号在任何异步边界变化时，中止当前提交，避免把 A 的正文写入 B 的作用域。

## 协议与吞吐

客户端以 25 条为一页拉取变化，并兼容：

- v2：请求 `since`，响应 `{ changes, cursor }`；
- v3：请求 `cursor, limit`，响应 `{ changes, nextCursor, hasMore }`。

较小分页配合逐页 durable checkpoint，可在服务端限流时继续前进；HTTP 429 优先遵守 `Retry-After`。若后端以后提供批量正文接口，应在 `SyncTransport` 内替换逐文件 GET，并保留相同的 apply/checkpoint 不变量。

## 用户操作语义

- 收藏：把本地文件纳入持续同步并立即生成首个快照。
- 取消收藏或从 Recent 移除：停止跟踪本地路径，但不删除云端副本。
- 删除已同步的真实文件：本地删除成功后生成云端 tombstone，避免其他设备把旧绑定复活。
- 删除纯 `cloud://` 文档：显式删除云端副本。
- 远端删除、正文分叉或绑定路径不可写：进入可见 conflict，由用户选择本地或远端版本。
