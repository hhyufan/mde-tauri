# 内容校验与压缩传输

## 功能是什么

同步前按 UTF-8 字节计算 SHA-256 摘要，对大文本按阈值进行 Gzip 压缩；远端正文只有在解压、size 与摘要全部通过后才允许写入本地并推进 checkpoint。

## 对应代码在哪

- 代码位置：[contentCodec.js](../../src/services/sync/contentCodec.js)
  符号：`COMPRESS_THRESHOLD_BYTES / MAX_SYNC_REQUEST_BYTES / MAX_SYNC_DECODED_BYTES`
  作用：定义压缩阈值和请求上限。
- 代码位置：[contentCodec.js](../../src/services/sync/contentCodec.js)
  符号：`encodeSyncBody / decodeAndVerifySyncBody / estimateSyncPayloadBytes`
  作用：负责压缩、解压、完整 JSON 请求体估算及 checksum/size 校验。
- 代码位置：[push.dto.ts](https://github.com/hhyufan/mde-server/blob/main/src/sync/dto/push.dto.ts)
  符号：`content / compressed / size`
  作用：服务端接收压缩传输的协议字段。
- 代码位置：[sync-document.schema.ts](https://github.com/hhyufan/mde-server/blob/main/src/schemas/sync-document.schema.ts)
  符号：`compressed / size / checksum`
  作用：服务端持久化压缩内容和校验信息。

## 关键代码怎么读

- 第一步看 [contentCodec.js](../../src/services/sync/contentCodec.js) 中的三个大小常量，区分压缩阈值、wire 请求上限和解压正文上限。
- 第二步看同文件中的 `encodeSyncBody / decodeAndVerifySyncBody`，理解正文必须先验证再 apply 的边界。
- 第三步看 [push.dto.ts](https://github.com/hhyufan/mde-server/blob/main/src/sync/dto/push.dto.ts) 中的 `content / compressed / size`，其作用是：服务端接收压缩传输的协议字段。
- 第四步看 [sync-document.schema.ts](https://github.com/hhyufan/mde-server/blob/main/src/schemas/sync-document.schema.ts) 中的 `compressed / size / checksum`，其作用是：服务端持久化压缩内容和校验信息。
